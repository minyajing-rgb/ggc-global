# GGC｜视觉锁定与逐批出图验收

适用基线：`GGC-CLOSED-DOOR-29P-V8-TEXT-20261007`。正文以 `MASTER_29P.md` 为准；v8 PDF仅作内容和页码参考，不继承它的粉色大底、渐变遮字或裁切故障。

## 1. 固定的视觉方向

- 每页是一张完整、独立的横版海报式PNG。最终用通过验收的29张图拼成29页PDF，不再在PDF导出时重算字体、渐变遮罩或卡片。
- 16:9统一画布；最终PNG建议1920×1080或2560×1440，同批与全稿尺寸统一。保持原比例；不得靠横向压缩字体、拉伸照片或裁掉文字强行凑尺寸。
- 白色底板为主；30%–50%留白是设计目标，保留内容的有效信息密度。大字层级、清楚的黑色正文、精炼的专业图示，不做稀疏口号页，也不做细字报告截图。
- 玫红—紫—蓝/青只用于关键词、数字、细线、小图标和很浅的局部底色。虹彩玻璃/极光只在边缘少量点缀，不盖住内容。
- 卡片接近白色，可用极浅粉、蓝、紫的细边与低对比底。禁止整片高饱和粉色卡片、荧光底铺满、彩色方块遮字。
- Logo使用Joyce / GGC；口号保留 `GLOBALIZE · GAMIFY · CONNECT`。以同一套标题尺度、正文尺度、边距、页码、图标线宽和颜色贯穿29页。
- 手写小字只能是装饰层，极少量；不得擅自新增口号、业务承诺或事实。与正文冲突时删除装饰，不删正文。

## 4. 每批固定的对照动作

工程上按S01–10、S11–20、S21–29准备三批；这是生产计划，不是工具能力上限声明。一次可连续调用工具完成一批，不要求用户重复确认已确定的文字。

### 生成前

1. 读取本目录README、AGENTS、MASTER与manifest；固定使用同一基线commit，记录所用commit SHA。
2. 运行 `python verify.py` 检查母稿完整SHA及29页分段SHA。运行 `python verify.py --prepare 01-10` 生成该批准确输入与空白验收表；第二、三批分别使用11-20、21-29。
3. 检查原照、原书封、获准参考图确实可用。缺资产时报告具体缺口，不能以旧生成肖像或想象资产替换。
4. 每页输入由该页完整正文＋本风格文件＋指定视觉素材构成，不由对话记忆临时重写。

### 生成后

逐页打开完整PNG，核对：标题与全文、每个数字/单位/限定、品牌与产品归属、白底浅卡片、无遮字/裁字/伪字、原照与书封、隐私。对照基线记录差异；失败页重做，不连带改动通过页。

每页记录 `source_sha256`、实际 `image_sha256`、检查结论和具体说明。状态由 `pending_generation` 到 `generated_unchecked`，核对后才可记为 `reviewed`。没有检查不能默认PASS；用户尚未审图时不能写“用户已批准”。

`verify.py --review batches/B01-10/qa.json`仅能验证文件、尺寸、哈希和人工/视觉验收记录是否齐备；它不会声称已经自动读懂图片或证明原始业务事实。默认不做OCR。

### 合成PDF前

29页全部完成同一基线与风格检查，确认S01至S29无缺页、重页、错序。只以最终PNG一图一页合成，不再重绘文字；重新打开成品PDF检查页面与PNG一致，核对封面、书页、长标题、数字页、报价与联系方式。PDF和单页PNG一并保留。
