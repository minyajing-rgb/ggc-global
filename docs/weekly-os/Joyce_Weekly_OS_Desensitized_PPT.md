# Joyce Weekly OS · 脱敏周报展示 PPT

> 用于每周对外/半公开展示：只展示事业部、产品阶段、生命周期、证据进度和下周动作；不展示客户名、真实金额、后台截图、私域联系人、邮件线程、token、仓库路径和原始数据。

## 1. 一句话定位

**JOYCE WEEKLY OS 是一个每周更新的 Portfolio Command Center：把散落在不同对话、网站、GitHub、Base44、PPT、邮箱和产品里的进度，归并成可展示、可验收、可复盘的脱敏看板。**

对外标题可用：

- 把进展，看清楚。
- 一屏看懂所有事业部在跑什么。
- 从散点资产，到可经营的产品宇宙。
- Progress with evidence, not noise.

## 2. 每周 PPT 推荐结构

每周 8–12 页即可，不做流水账。

1. **封面**：本周主题 + 日期 + 一句话结论。
2. **本周总览**：4 个数字即可，例如资产单元、证据确认率、待核实节点、完整连接验收。
3. **七大产品宇宙**：每个事业部一张卡，只讲进度、状态、下一步。
4. **生命周期 01–09**：市场研究 → 立项需求 → 架构 Demo → 测试验收 → 商业测试 → 上线发布 → 分发获客 → 留存经营 → 复盘扩展。
5. **RAG 状态板**：已确认 / 进行中 / 待拍板 / 待核实。
6. **本周重点变化**：最多 3 件，必须有证据或待验收动作。
7. **脱敏案例页**：用 Project A / Product B / Partner C，不暴露真实对象。
8. **Public Share Pack**：一个产品 3–5 张朋友圈图。
9. **下周拍板事项**：最多 3 件。
10. **封底 CTA**：更清晰的产品宇宙，更稳定的经营节奏。

## 3. 一个产品 3–5 张朋友圈图

每张图只讲一个结论。

1. **这是什么**：一句话定位。
2. **解决什么**：Top 3 痛点 / 机会 / 风险。
3. **怎么做**：流程图、架构图、关键步骤。
4. **为什么是我**：经验、能力、方法、视角。
5. **Before → After & ROI**：真实改变、节省、提升、下一步。

## 4. 脱敏规则

| 类型 | 不展示 | 替代表达 |
|---|---|---|
| 客户 / 合作方 | 客户名、联系人、邮件线程 | 某出海项目 / 某海外合作方 / 某平台入口 |
| 收入 / 投放 | 真实收入、预算、CPI、ROI 细表 | 商业测试已建立 / 成本口径已进入复盘 |
| 代码 / 仓库 | 私库路径、token、后台截图 | 研发链路已接入 / 自动化工具进入测试 |
| 人脉 / PR | 私人微信、未确认奖项结果 | 媒体/大会申请进入跟进期 / 资方触达中 |
| 用户 / 数据 | 原始用户数据、个人信息 | 行为信号已归类 / 反馈进入需求池 |

## 5. 每周 60 秒讲稿模板

> 本周我把散落在不同对话、仓库和页面里的项目，统一归到一个 Weekly OS。公开版只展示事业部、产品阶段、证据确认率和下周动作，不展示客户名、金额和私域信息。当前最关键的不是做更多图，而是打通三个闭环：收费交付、内容到线索、核心循环验收。下周我会重点看红黄绿蓝状态：哪些已确认、哪些推进中、哪些要拍板、哪些必须继续核实。

## 6. 视觉规则

- 浅色底板优先：奶白 / 浅蓝 / 浅粉。
- 玫红 = 重点；电蓝 = 数据；紫色 = 系统；橙色 = 待拍板；绿色 = 已确认。
- 大标题要像产品海报，不像工作汇报。
- 人像只放封面、封底、章节页，不要每页都放。
- 正文尽量 18pt+，每页只放一个主结论。
- 少用密集表格，多用进度条、生命周期、状态卡。

## 7. 每周更新 Checklist

- [ ] 本周日期与版本号已更新。
- [ ] 所有客户名、金额、联系人、后台截图已脱敏。
- [ ] 每个事业部都有状态：已确认 / 进行中 / 待拍板 / 待核实。
- [ ] 每个数字都有证据来源或明确标注为待核实。
- [ ] 下周最多 3 个拍板事项。
- [ ] 对外朋友圈图不超过 5 张，一图一个结论。
