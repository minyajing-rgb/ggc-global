# GGC 全站实施 PRD / Accepted Implementation Baseline

版本：2026-10-12 · 状态：按已确认全站UI实施。沿用 PR #11，不另起视觉方向。

## 1. 产品定位与目标
GGC / Global Game Copilot 是以全球游戏与互动娱乐实践为基础的战略前瞻与经营决策实验室。首页必须回答：行业往哪里走、贵司真正的问题在哪里、适合做什么、缺少哪些能力和资源，以及下一步如何执行。公司品牌在前；Joyce肖像、旗舰项目经历和著作为专业证据，不替代公司业务。

从用户已认可模板继承：现代粗黑体大标题，白底、玫红/蓝紫激光炫彩、轻薄半透明决策面板；只用已选择的01/04/06/08/09/10按钮。保留已有职业事实纠正、16个服务ID、中英文对照、四大业务和方法体系。

## 2. 主要访问者与结果
- 创始人/经营负责人：专业能力 → 具体服务 → 有上下文的商务联系。
- 研发/发行团队：联合立项 → 项目阶段/能力匹配 → 项目讨论。
- 投资及产业伙伴：研究/产品/Why GGC → 了解商业与团队条件 → 合作讨论。
- 软件/消费者：产品目录 → 产品详情 → 已确认产品入口；与B2B线索分开。
- 行业读者：研究目录 → 方法说明/原始资料 → 自愿表达订阅意向。

## 4. 功能与阶段验收
P0-01 所有页面与深层链接有对应locale，语言切换保持语义同页。
P0-02 导航/菜单/页尾/CTA可用，不出现没有目标的按钮。
P0-03 服务按ID跳转，详情到联系表携带service；原范围与限定数值不被宣传海报价格覆盖。
P0-04 研究分类、服务搜索与产品筛选有可访问的选中态与空结果。
P0-05 示例明确是方法示例，不能伪装实时分析或真实客户结论。
P0-06 画廊说明图不能标为真实App截图；开发方向不是已注册子公司。
P0-07 肖像使用已给素材裁切，保留来源；不生成新的人物替代。
P0-08 当前表单只生成用户自行发送的草稿。未接API时不得显示已投递/已订阅。
P0-09 320/390/768/1440布局、标题不裁切，Tab/Escape/箭头键可用。
P0-10 导入同一GitHub工程、隔离开发路径、构建记录及回滚点。

P1-01 真实询单API：保存成功才出receipt；幂等重试、反垃圾、通知失败告警与CRM职责归属。
P1-02 订阅：独立同意、待确认/已确认分离、退订、抑制名单，不能从询单自动订阅。
P1-03 研究原稿/真实产品截图/可公开案例按权限逐项接入。
P1-04 主站部署：HTTPS、root/www规范化、SEO/hreflang/sitemap、404实际HTTP状态、正式隐私条款。

## 5. 明确不包含
不重新设计SAGA式世界大厅；不扩大肖像占比；不编造客户/合作方、数量、NPS、收入、已发布报告和公司数；不公开私人行业交流；不自动购买云服务；不改MX、SPF、DKIM、DMARC或无关子站。

## 6. 业务闭环边界
当前交付为可运行前端。网站能打开、按钮能点击不等于CRM或订阅已完成；两者分别验收。正式发布不应被宣传为“全部完成”，除非P1服务和域名检查有实际回执。

## 7. 来源
内容和结构以用户本对话最新确认、全站V4包、已审过的corporate/implementation代码、joyce/content/services.json、所给Joyce Method与九页原海报为准。引用海报的方法与书籍主题时保留其组织，不推断未提供原始报告的新发现。
