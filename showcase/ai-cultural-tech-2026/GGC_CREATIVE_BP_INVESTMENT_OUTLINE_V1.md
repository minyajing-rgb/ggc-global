# GGC Creative / FlowMedia AI — 投资主张与独立 BP 大纲 V1

**项目身份已核对：** `sme/README.md` 将 **GGC Creative** 列为 GGC 五个正式产品方向之一；`sme/docs/GGC_CREATIVE_PRD_v1.md` 已定义移动端 PRD，并说明复用 **FlowMedia AI** 已有 Create Studio、Content Library、Analytics、GenerationJob 等模式。**Build-ready PRD != 已完成收费产品或视频生成引擎。**

**与 GGC Traffic OS 的界线：** 
- **GGC Creative = 创意与视听生产 / 创意决策、脚本分镜、产线与测试学习。** 客户是制作人、创意策略/广告素材团队、游戏/App。
- **Traffic OS = 全球渠道分发 / 受众触达、获客、转化归因与发行经营。** 可采购 Creative 生产成果，但产品、合同、权属、收入不能重复计量。
- 官方赛事类别名称、实际 AI 视频制片/render 资格尚未核实。不能把计划引入的版权/渲染能力说成已完成。

## 投资故事（先讲发现，再讲未来）

**市场观察：** AIGC 降低了脚本、图片和视频素材制作门槛；Creatify、Pencil、Smartly 等竞争者已覆盖创意生成及部分投放工作流，意味着“会用 AI 生成内容”不是护城河。

**发现的空缺：** 对游戏和 AI 应用团队而言，选题对不对、Hook 是否匹配产品、分镜能否交给制作方生产，以及每轮真实结果能否指导下一轮，往往比增加生成数量更关键。这个空缺仍需通过客户访谈和测试结果验证，不能当成已经取得领先地位。

**我们的切入：** 把**产品与用户研究 → 创意角度选择 → Hook/脚本/分镜 → 可执行制作包 → 变量清楚的测试矩阵 → 真实结果回填 → 下轮推荐**做成标准产品。第一个客户能在几分钟内拿到可执行创意方案，后续每轮测试留下可复用、经许可的数据和判断。

**为什么是 Joyce 团队：** Joyce 历史上负责旗舰游戏的产品经营、数据/实验、商业化与全球发行，能够把“素材看起来不错”转成“要验证哪个玩家行为和经济指标”；但这并不自动证明 Creative 已有稳定付费客户。技术负责人、创意制作与实验数据能力须依产品计划实际配备。

**发展目标：** 从一个明确“今天该测试什么”的创意决策产品，拓展成**有权属记录、创意实验数据和跨内容形式的 AI-native 制作协作基础设施**。完整制片渲染、音视频一致性与训练/推理优化是独立验证的后期能力，不写成 v1 既有能力。

| 页 | 投资结论标题 | 页面讲什么 / 证据形态 |
|---|---|---|
| 01 | **从创意数量到商业上可验证的内容生产** | 正式名称 GGC Creative / FlowMedia AI、法人候选与产品阶段。 |
| 02 | **AI 生成门槛在下降，但“该做哪条”仍需判断** | 具体游戏/App素材制作流程与失误成本；用户访谈待补。 |
| 03 | **好内容不是生成出来就结束，而是形成下次更好的判断** | 从 brief 到结果学习的完整价值循环。 |
| 04 | **现有竞品已能生成视频，我们不以“也会生成”参与竞争** | Creatify、Pencil、Smartly、Canva、Runway 分成同类/相邻/技术供应商；逐项核对功能、价格和出处。 |
| 05 | **切入市场先从真实有投放需求的游戏/App 团队开始** | 首个 ICP、预算负责人、选品条件、当前替代方案；市场 TAM/SAM/SOM 按底层可服务客户数计算。 |
| 06 | **创意团队今天的工作流跨工具割裂，损失发生在交接和学习** | 发现、评审、生产、测试、反馈各环节成本/时间基线；不能凭感觉编数字。 |
| 07 | **最小可销售产品不是视频引擎，而是“知道下次该测什么”** | 一次创意诊断＋脚本分镜＋6格矩阵＋结果记录；PRD 界定的视频渲染非 P0。 |
| 08 | **给出产品后，三分钟形成能执行的创意方向** | 输入 URL/截图/产品说明，产出 3 angles / 5 hooks / 1 script / 1 matrix，为目标验收不是现网业绩。 |
| 09 | **把创意假设转成完整生产包** | Hook、15秒脚本、分镜帧、机位/旁白/画面、素材清单/供应商交付说明。 |
| 10 | **结果不是一条 CTR，而是带来源的创意知识** | 区分自有测试、竞品观察、品类模式、模型假设；谁能看到、数据合法性。 |
| 11 | **与传统创意外包比较：不是省一位编辑，而是提高决策复用率** | 交付周期、人效、版本修改率、测试结果回收率；差异待实证。 |
| 12 | **技术优势来自五层可控工作流，而非包装成自研大模型** | 多模态输入、分析评分、生成、实验编排、学习回填，外部模型与自建数据边界清楚。 |
| 13 | **版权链决定企业客户是否敢采用 AI 产物** | 原始资料来源、授权、人物/声音权利、生成资产元数据、修改与版本、导出审计；规划中逐项明确。 |
| 14 | **AI 制片是扩展能力：不能与当前 storyboard 原型混为一谈** | 当前：脚本分镜/参考图/提示词；将来：音视频生成、角色一致性、渲染排队与成本控制。 |
| 15 | **为何 Joyce 的既有操作系统能缩短商业验证路径** | 创始人直接责任（游戏产品经济、实验、发行）、可验证历史成果与它对应的产品决策。 |
| 16 | **从 FlowMedia 复用已建能力，但把产品改造成垂直需求** | 已有结构：Create Studio、Content Library、Analytics、GenerationJob；需要重新实现的产品业务逻辑。 |
| 17 | **当前阶段：有产品目录与 PRD，不等于完成商业验证** | 真实截图／运行链接／演示状态／缺失 P0 与测试证据；状态分已观测、计划中、未验证。 |
| 18 | **付费从创意诊断开始，软件订阅要有重复使用理由** | 免费审阅、Pro/Team 席位、企业工作流、交付/定制分开测；报价与合同未批准。 |
| 19 | **商业模型最核心变量：每个账户留存和每条可测试创意的成本** | 账户数、付费率、ARPA、席位、LLM/图片/API支出、QA/人工时、退款和销售佣金。 |
| 20 | **先交付可复验的付费试点，再扩大团队和渠道** | 三阶段：原型闭环→真实测试数据→客户复购；明确 KPI 和否决条件。 |
| 21 | **融资后的团队不应复制 Traffic OS 的营销/销售编制** | Product/Creative Lead、全栈/AI 集成、创意技术/视听制作、数据/QA、版权合规按节点安排。 |
| 22 | **每笔投入必须对应一项更强的可交付能力** | 按月份拆招聘、模型/媒体生成费用、内容资产、测试样本、风险预备金，先用真实报价反推融资额。 |
| 23 | **三年财务只靠驱动项，不靠拍一个增长率** | 月付费账户×ARPA、消费量、服务交付收入分拆；毛利与现金流情景、延期/成本敏感性。 |
| 24 | **投资结果：建设垂直 AI 创意操作系统，而非素材代工团队** | 可复用知识资产、企业团队使用、商业拓展与独立营收；Joyce 联系方式与合作边界。 |

## 核心可验 KPI（尚非已实现结果）

- 首次可交付 brief 所需时间；brief → 完整制作包完成率；人工修订/审查所需时间。
- 创意测试矩阵被实际采用的比例；结果回填比例；次轮建议的证据可靠性。
- 7日/30日活跃客户比例；付费转换率与客户级毛利；每账户 AI/素材生成成本。
- 若加入视频模型：每秒合规可用视频成本、失败重试、角色一致性、渲染队列时延，以及真实授权覆盖率。
