# GGC A+B Loop & Content Editor · v1.0

**[打开单文件编辑器源码 / 下载 HTML](index.html)**

一个无需安装依赖的、浏览器直接打开的可视化编辑器，用于拆解和设计 **A = Spin/Dice 随机核心 + B = Village/Board/Collection/Social/LiveOps** 的游戏内容生产与运营闭环。

> 重要：示例图是公开玩法的**结构示意**，不代表已取得任何竞品的内部配置、概率、RTP 或确切内容库存。**当前录入数量 ≠ 竞品现有机台总量，也 ≠ 客户端每月新增机台数。**

## 已实现

1. **多项目可视化流程**：内置 Coin Master、MONOPOLY GO!、Dice Dreams、Coin Master – Board Adventure 四个独立工作区。可以创建自己的项目；拖动节点、连线、编辑资源来源／消耗、回访目标，校验是否存在 A → B → A 回路。
2. **内容库存编辑**：每条内容选择真正的单位：Slot Machine / Village / Board / Album / Sticker Set / Pet / Event / Social / Feature。记录名称、App 版本、首次观察日期、状态、来源链接和证据备注。
3. **A / B / C 规则差分**：A 换皮（机制相同）、B 新规则（机制变化）、C 不明确。提供 Reel/Row、Paylines/Ways、Bonus Trigger、Hold & Spin、Jackpot、Math/RTP 字段，还可编写 Before / After，选择已录入的前代内容作对照。
4. **有证据门槛的分类**：仅当记录有效 HTTPS 来源、旧规则说明、新规则说明及相匹配的“是否变化”申报后，才将记录计入 A 或 B；否则**自动列入 C**。这是录入资料的形式校验，**并不等于独立验证事实**。
5. **版本与更新口径**：首发 / 客户端版本 / 配置热更 / 运营活动分开。跨版本同一个内容 ID 不重复累计。
6. **横向对标 / 审核**：显示各项目已经*录入*的内容与 A/B/C 数量，检查 A → B 和 B → A 路径、缺失的官方来源与未能确认的规则。
7. **JSON / CSV 双向工作流**：在浏览器本地自动保存；导出全部项目 JSON（可再导入）和完整内容 CSV，便于 GitHub PR 审核及后续数据管线。

## 使用

1. 从 GitHub 打开 `index.html` 文件，使用 **Download raw file** 下载到本地；双击用 Chrome / Safari / Edge 打开。不依赖 npm、API Key 或在线服务。若仓库启用了 GitHub Pages，可以将该目录设为静态资源路径。
2. 从“项目”下拉选择四个 A+B 对照样本，或创建自有项目。
3. 在 **01 A+B 流程编辑** 中添加并拖动节点，点“连接节点”，依次点起点与终点；点击节点或连线可编辑 Inspector 字段。
4. 在 **02 内容库存** 里创建具名内容记录。不要把“新皮肤 / 新机台名”直接推断为“全新数学规则”；没拿到对照证据时选 C。
5. 在 **03 版本 / 规则差分** 标记首次公开时间、版本号与上线类型，并用“差分”对照六个 Slot 专用规则字段。
6. 在 **04 核验 / 横向比较** 查看结构缺口和研究证据缺失，再导出 JSON / CSV。

### 如何理解 A/B/C

| 结果 | 最小录入证据 | 限制 |
|---|---|---|
| A · 换皮 | 官方／可靠的 HTTPS 证据 + 前后规则描述 + 声明机制一致 | 仅凭图标、主题或名称不同不可判定 |
| B · 新规则 | 官方／可靠的 HTTPS 证据 + 前后规则描述 + 声明机制改变 | 机械变化应具体落到 Trigger / Reel / Jackpot / Meta Resource Rule 等 |
| C · 不明确 | 任何证据不足、描述冲突、不确定的新机台 | C 不是 0，也不是默认换皮 |

**差分编辑器只是整理人工核验材料，不会通过文本比较自动证实 RTP、中奖概率、数学实现或“独立机台数”。** 对 Coin Master、MONOPOLY GO!、Dice Dreams 这类 A+B，核心 Spin/Dice 轮次、Village/Board 的数量、Album 与 LiveOps 的数量分别统计；不能把 Village、地图或卡册算作 Slot Machine。

## 数据结构

- `projects[]`: 彼此隔离的游戏研究工作区，可自建
- `nodes[]`: 拖拽节点及 A / B / 资源 / 活动组件字段
- `edges[]`: 有方向的机制依赖、产消和回流链接
- `content[]`: 内容 ID、单位、版本、上线状态、规则差分、证据、人工分类
- `versions[]`: 发布时间、发行类型、来源
- `schema`: `ggc.ab.editor.v1`

**存储与权限**：当前只使用浏览器 `localStorage`，不传输到服务端，也没有账号同步、多人协作、GitHub OAuth 或发布到游戏服务端的功能。清理浏览器数据、换设备或无痕模式可能丢数据，请及时导出 JSON 作为自己的备份。

**敏感信息**：本目录设计为可共享的通用产品研究工具；不要把合作客户的未公开机台资产、真实 RTP／数学配置、收入、个人数据或保密项目资料提交到公开仓库。
